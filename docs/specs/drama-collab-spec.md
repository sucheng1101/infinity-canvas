# 短剧协作版：剧组模型（v2）

> 覆盖 v1 的「定妆→分镜→预演→拍摄」线性流程。核心变化：**只有剧本是前置，其余全部并行**，并按真实剧组分工划分编辑范围。

## 1. 为什么改

v1 的问题：把五个步骤做成串行向导，等于假设一个人从早做到晚。真实剧组不是这样——导演定剧本，美术在搭景，服化道在准备角色，摄影在排机位，**同时进行且互不阻塞**。

## 2. 核心结构

```
项目
├─ 剧本（唯一前置）
└─ 四个并行工作面板（无先后顺序）
    ├─ 素材（原定妆）  角色 / 造型 / 场景 / 道具 — 美术·服化道
    ├─ 分镜            镜头表 + 每镜场景图 — 导演·摄影
    ├─ 预演            多镜头连贯演示全场景 — 导演
    └─ 拍摄            任务队列与产出 — 制片
```

谁先谁后由团队自己决定；系统只保证**改一处不会把别人的活冲掉**。

## 3. 剧本：支持导入小说

- 粘贴文本（现有）
- **导入文件**：`.txt` / `.md`，拖入或选择；解析编码（UTF-8 / UTF-8 BOM / GBK 回退），失败给中文提示
- **章节切分**：小说按「第X章」或空行分块，用户选一段作为本次短剧的素材，避免一次塞十万字
- 存 `DramaProject.script`（原文）+ `scriptSegments`（章节列表）

## 4. 素材（原定妆）——资产库 + 任务

### 4.1 角色要有「造型」

```ts
type Costume = { id: string; name: string; prompt: string; refImages: string[] };
type CharacterCard = {
  id: string; name: string; prompt: string; heightCm: number; color: string;
  costumes: Costume[];      // 几套衣服，每套自己的描述与参考图
  activeCostumeId?: string; // 当前造型，镜头可覆盖
};
```

镜头里可以指定用哪套造型（`shot.costumeOverrides: Record<characterId, costumeId>`），这样「同一角色第 3 场换成夜行衣」不需要复制角色卡。

### 4.2 任务挂在资产上

```ts
type AssetTask = {
  id: string;
  target: { kind: "character" | "scene" | "prop"; id: string; costumeId?: string };
  kind: "image" | "costume" | "prop" | "voice";
  status: "待做" | "进行中" | "已完成" | "失败";
  outputUrl?: string;
  assignee?: string;   // 后续接协作时填成员
  note?: string;
};
```

素材页顶部显示**任务总览**：「角色 4 / 造型 7 / 场景 3 / 道具 5 / 待完成 6」，点进去看每个资产的任务与产出图。这就是用户说的「有多少任务、人物照片什么样、有几套衣服」。

### 4.3 按剧本自动建资产

剧本解析（一次文本模型调用，输出结构化 JSON）：

```
剧本 → { characters: [{name, description, costumes: [{name, prompt}]}],
          scenes: [{name, summary, templateHint}],
          props: [{name, description}] }
```
每个资产自动带一张「待生成」任务，用户点一下批量出图即可。

## 5. 分镜：自动生成场景图

- 拆分镜后，每条镜头自动生成一张「场景图」（用现有图片模型，并发 3，走积分）
- 场景图可提前改：直接编辑提示词后重出，或上传自己的图替换
- 镜头表增加「场景图」列（缩略图 + 状态）

## 6. 预演：多镜头连贯

v1 只能单镜头预览。v2：

- 顶部一个**时间线**：把所有镜头按 `index` 顺序排开，总时长 = 各镜时长之和
- 播放时相机按当前镜头关键帧运动，播完自动切到下一镜（硬切），形成**全场景连贯预演**
- 支持「只看本镜 / 连续播放」切换；连续播放时可调 1x / 2x 速度
- 每个镜头的白模场景可以不同（不同场景卡），切换时重建场景

实现要点：`PrevisCanvas` 目前只接收单 `shot`，需要提升为接收 `shots: DramaShot[]` + `playhead` 状态，由父组件驱动切换。

## 7. 协作（多人同步）

分两期，先把结构留出来：

**第一期（本地多人视图）**
- 成员列表与角色标签：导演 / 美术 / 服化道 / 摄影 / 制片
- 每个资产与镜头带 `updatedBy`、`updatedAt`，界面显示「谁最后改的」
- 编辑互不阻塞：不同面板各自保存，不互相锁定

**第二期（实时同步）**
- 需要后端同步层（WebSocket + 操作合并）。当前架构是纯本地 IndexedDB，实时协作要么接 Yjs/Automerge 做 CRDT，要么上服务端版本号 + 冲突提示
- 建议先用「乐观编辑 + 冲突提示」：保存时比对版本号，冲突就提示「张三刚改过这个镜头，你的改动画到了副本」

## 8. 权限（按部门）

| 部门 | 可编辑 | 只读 |
| --- | --- | --- |
| 导演 | 剧本、分镜、预演 | 素材产出 |
| 美术 | 场景、道具 | 剧本、镜头顺序 |
| 服化道 | 角色造型、参考图 | 镜头表 |
| 摄影 | 镜头机位、景别 | 剧本 |
| 制片 | 任务分配、积分 | 内容 |

第一期只做**界面分区 + 标签**，不做强制拦截（避免单人用户被自己的权限卡住）。

## 9. 分期

| 期 | 内容 | 可独立验收 |
| --- | --- | --- |
| P1 | 剧本导入文件 + 章节切分 | 导入一本小说，选一章进入 |
| P2 | 角色造型（多套衣服）+ 资产任务 + 按剧本自动建资产 | 建一部戏，看到 4 角色 7 造型和待办数量 |
| P3 | 分镜自动场景图 + 可改 | 拆分镜后自动出图，改提示词重出 |
| P4 | 多镜头连续预演 | 时间线播放，镜头自动切换 |
| P5 | 成员标签 + 最后修改人 | 显示每个资产的编辑者 |
