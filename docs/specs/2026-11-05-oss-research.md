## 3. 结论：我们该抄什么

### 3.1 必须抄（决定能否做短剧）

1. **资产层独立于画布**（Toonflow / ArcReel）
   角色、场景、道具必须是**可复用的一等对象**，而不是画布上的临时节点。跨镜头一致性靠「同一张资产卡 + 参考图」复用，而不是每次重新描述。
2. **结构化分镜数据**（Jellyfish / ArcReel）
   镜头不是自由排布的图片，需要 `场次 → 镜头 → 时长 → 台词/旁白 → 参考资产` 的字段。画布可以是它的可视化形态，但数据必须有结构。
3. **异步任务中心**（Jellyfish）
   短剧必然出现「几十个镜头排队生成」。我们现在的 Relay 是同步执行，一个请求占住一个 goroutine；必须先有任务中心，再做分镜批量生成。
4. **多宫格分镜图**（ArcReel）
   一次生成 4/6/9 宫格分镜，是短剧最省钱的第一步：先定构图和节奏，再逐镜出高清图视频。

### 3.2 值得抄（体验差异点）

5. **剪映草稿导出**（ArcReel）：中国创作者的实际终点是剪映。至少先导出「分镜图 + 视频片段 + SRT 字幕 + 素材清单」的工程包；剪映草稿 JSON 可作为 v0.25 目标。
6. **生成前后费用可见**（ArcReel）：我们已有积分与计价，缺的是「生成前报价 + 生成后实扣」的对照展示。
7. **可搜索 + 存进自己的库**（ChatGPT-Shortcut）：词库不只是浏览，核心是「搜到 → 一键用到画布 → 顺手收藏成私有词条」。
8. **提示词案例可溯源 + 跨模型重测**（awesome-seedance）：词条要带「在哪个模型上验证过、效果如何」，这比堆数量有价值。
9. **关键阶段确认 + 单素材重做 + 历史回滚**（ArcReel）：与我们画布的撤销重做、节点重生成天然契合，需要补「版本」概念。

### 3.3 不要抄

1. **不要做纯表单流水线**（Jellyfish/ArcReel 的形态）：他们牺牲了自由度换取流程确定性；我们的差异恰恰是「画布可自由拼装」。做法是：画布为壳，分镜为结构化视图。
2. **不要做 21 种界面语言**（Toonflow）：维护成本高。中英双语足够，其余按需。
3. **不要做 DAG/CPM 调度**（forge-film）：那是云渲染农场式批处理；我们的用户在画布上逐个确认镜头，不需要拓扑调度。
4. **不要做本地推理引擎**（Open-Generative-AI 的 sd.cpp/Wan2GP）：与我们的托管 SaaS 模式冲突。
5. **不要堆模型数量**：600+ 模型是他们的卖点，我们的卖点是「选对模型 + 成本可控」。

## 4. 据此修正的设计

### 4.1 导航（在上一版基础上微调）

```
创作（工作台：图片 / 视频 / 分镜成片）
画布（我的项目：自由画布 / 电商套图 / 短剧分镜）
素材（资产库：角色·场景·道具 ｜ 媒体库：图/视频/音频 ｜ 模板）
灵感（词库：结构化词典 ｜ 案例：可复现作品 ｜ 社区来源）
我的（额度、订阅、渠道、用量、设置）
```

与上一版的差异：**「素材」下明确分出「资产库」与「媒体库」**——这是 Toonflow/ArcReel 验证过的结构，角色/场景/道具和普通素材不是一回事。

### 4.2 数据结构（关键改动）

```ts
// 资产：跨项目复用的一等对象
type Asset = {
  id: string;
  kind: "character" | "scene" | "prop" | "media";
  name: string;
  refImages: string[];        // 参考图（角色三视图、场景多角度）
  prompt: string;             // 固化描述
  tags: string[];
  license: "own" | "ai" | "licensed";
};

// 镜头：分镜的最小单位
type Shot = {
  id: string;
  sceneId: string;
  order: number;
  durationSec: number;
  shotSize: "特写" | "近景" | "中景" | "全景";
  camera: "固定" | "推" | "拉" | "摇" | "移" | "环绕";
  dialogue?: string;          // 台词/旁白
  assetRefs: string[];        // 引用资产 id（一致性来源）
  prompt: string;
  imageNodeId?: string;       // 落到的画布节点
  videoNodeId?: string;
};
```

画布节点通过 `metadata.assetRole / shotId` 关联，**画布仍是编辑入口**，结构化数据在侧栏/分镜视图里编辑。

### 4.3 任务中心（必须先做）

- 复用现有 `generation_tasks` 表与 Relay，把「同步执行」改为「入队 + worker 消费」。
- 前端新增任务中心抽屉：排队/生成中/成功/失败，可取消、可重试、可跳回节点。
- 这是分镜批量生成的前提（一个 20 镜短片 = 20+ 次生成）。

### 4.4 词库（结合 awesome-seedance 与 ChatGPT-Shortcut）

- 词条字段：`category / zh / en / aliases / params / verifiedModels[] / exampleUrl`。
- 「验证模型」字段很重要：同一个「电影感人像」在 Flux 和 Seedream 上写法不同。
- 入口三个动作：搜索 → 插入到当前节点 → 收藏到私有库。

### 4.5 材料库

- 分「资产（角色/场景/道具）」与「媒体（图/视频/音频）」两类，标签 + 集合 + 授权。
- 必须上云：本地 IndexedDB 无法支撑跨项目复用与团队协作（Toonflow 用工作区目录，ArcReel 用服务端存储，都印证了这一点）。

## 6. 风险与取舍

1. **同质化**：Toonflow（20k★）和 ArcReel（6k★）已经把「短剧 + 画布/流水线」占住了。我们的差异必须落在**「电商 + 短剧共用一套资产与画布」**以及**商业闭环**上，否则就是慢一版的复制品。
2. **成本**：分镜批量生成会显著放大视频生成成本，任务中心必须配预算上限与失败即停。
3. **合规**：角色/场景资产涉及肖像权与版权，素材库的 `license` 字段与上传协议要先于功能上线。
4. **维护面**：插件市场 + Agent + 分镜 + 素材 + 词库同时推进会摊薄精力，建议按上表顺序，每版只开一个新面。
