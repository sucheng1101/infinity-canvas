# 运营能力加固 Spec：渠道、订阅、成本与安全边界

## 1. 目标与范围

本阶段把“自定义渠道可用性、订阅/解锁扣费、成本利润记账、密钥配置”从可用原型收敛为可重复、可追溯的运营能力。范围包含：

- 自定义渠道必须精确绑定用户选择的公开模型与渠道模型；渠道权益失效后立即停止调用。
- 订阅购买和自定义渠道解锁购买使用客户端请求幂等键，重复请求返回第一次成功结果，不重复扣积分、不重复创建权益。
- 使用日志保存调用时的成本/售价快照，后续修改定价不影响历史利润。
- 进程重启后的超时任务回收必须回退订阅额度。
- 生产环境拒绝默认渠道加密密钥，开发环境仍可使用默认值。
- 修复套餐模型显示名，增加数据库级成本价格唯一约束。

不包含：支付网关接入、账单页面重做、已有历史数据迁移、与本阶段无关的画布功能调整。

## 2. 数据模型

### 2.1 订单幂等

新增 `OperationOrder`：

| 字段 | 规则 |
| --- | --- |
| `ID` | 主键 |
| `UserID` | 用户 ID，索引 |
| `OrderNo` | 服务端生成，唯一 |
| `IdempotencyKey` | 客户端请求键，按 `UserID + Type + IdempotencyKey` 唯一 |
| `Type` | `subscription_purchase` 或 `channel_unlock` |
| `ProductID` | 订阅计划或解锁计划 ID |
| `Amount` | 实际扣除积分快照 |
| `Status` | `processing`、`succeeded`、`failed` |
| `ResultJSON` | 成功结果快照，避免重复请求重新计算 |
| `ErrorCode` / `ErrorMessage` | 失败结果 |
| `CreatedAt` / `UpdatedAt` | 审计时间 |

订单创建、余额扣减、权益创建、结果写入必须在同一数据库事务内完成。收到相同幂等键时先返回已完成结果；首次请求失败时保留失败状态，客户端可使用新幂等键重试。

### 2.2 使用日志价格快照

在 `UsageLog` 增加：

- `CostPricingID`：命中的成本价格记录 ID；
- `CostPerUnit`：成本单价积分快照；
- `SellPerUnit`：售价单价积分快照；
- `CostTotal`：成本总积分；
- `RevenueTotal`：收入总积分（等于实际扣除积分）；
- `ProfitTotal`：利润总积分。

原有 `CostQuota`、`ProfitQuota` 继续作为兼容展示字段，并与新字段保持相同数值。

### 2.3 成本价格唯一性

`ModelCostPricing` 对 `(published_model_id, channel_id, upstream_model, status)` 建立唯一约束，后台更新采用更新现有记录而不是制造重复活动价格。

## 3. 服务规则

### 3.1 自定义渠道路由

- 前端选择 `user-channel:<channelID>::<channelModel>` 时，必须将该渠道模型映射到能力一致的公开模型；不能使用候选列表第一项代替映射。
- 映射不到公开模型、渠道不存在、模型隐藏或能力不一致时，直接返回明确错误，不回退到默认公开模型。
- `userchannel.Resolve` 与生成任务创建都要校验至少一个未过期的 `UserChannelEntitlement`，并在创建阶段再次校验权益数量，防止权益在列表加载后过期。

### 3.2 订阅购买与额度

- 购买请求必须携带幂等键；服务端为空时生成一次性键仅用于兼容旧调用，正式客户端始终发送随机键。
- 重复幂等键返回原订阅视图，不再次扣除余额、不重复结束旧订阅。
- `reapStaleTasks` 注入 `Subscriptions` 服务，使超时、失败、取消路径统一回退已消费订阅额度。
- 套餐视图通过 `PublishedModelID` 填充 `PublishedModel.DisplayName`。

### 3.3 渠道解锁

- 解锁购买与订阅购买使用同一订单幂等机制。
- 幂等键重复时返回原 `UserChannelEntitlement`。
- 解锁权益有效期按 UTC 计算；过期权益不计入可用渠道数量，也不能用于解析或创建任务。

### 3.4 成本/售价结算

- 任务结束时读取当前命中的活动成本价格，并立即把单价、价格记录 ID、成本、收入、利润写入 `UsageLog`。
- 后续价格修改只影响新调用；历史日志完全依赖快照字段。
- 失败调用收入为实际扣除积分（通常为 0），成本和利润按实际产生的调用量计算。

### 3.5 密钥安全

- `CHANNEL_ENCRYPTION_KEY` 为空时开发环境继续使用本地默认值。
- 当 `APP_ENV` 为 `production`、`prod` 或 `release` 时，若仍使用默认值或长度不足，启动直接报错并停止服务。
- 错误信息只指出配置无效，不输出密钥内容。

## 4. API 变更

- `POST /api/v1/subscriptions/orders` 请求体增加 `idempotencyKey`，并支持 `Idempotency-Key` 请求头。
- `POST /api/v1/account/channels/unlock` 请求体增加 `idempotencyKey`，并支持 `Idempotency-Key` 请求头。
- 管理端成本价格列表/编辑接口返回快照字段对应的单价单位和利润率；现有接口路径保持不变。
- 重复幂等请求返回 HTTP 200 与第一次成功响应，业务响应结构不变。

## 5. 验收标准

1. 同一用户用同一幂等键重复购买订阅，余额只减少一次，只有一条成功订单和一条订阅。
2. 同一用户用同一幂等键重复解锁渠道，余额只减少一次，只有一条有效权益。
3. 解锁过期后，渠道列表显示不可用，创建任务和路由解析均被拒绝。
4. 自定义渠道选中具体模型时，请求发送到该渠道模型；模型映射失败时不会调用默认渠道。
5. 修改成本价格后，旧 `UsageLog` 的成本单价、售价单价、成本、收入、利润保持不变。
6. 重启后回收超时任务时，订阅额度恢复与在线失败路径一致。
7. 生产配置使用默认或过短渠道加密密钥时服务启动失败；非生产配置行为不变。
8. `go test ./...`、前端类型检查、前端构建和本地健康检查通过。
