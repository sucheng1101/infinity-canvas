# 运营平台第二、第三阶段 Spec

## 状态

Implementation Approved。第二、第三阶段在第一阶段“运营能力加固”之上继续落地，保持现有用户、计费、渠道、订阅和本地画布行为不变。

## 第二阶段：运营可见性与账务闭环

### 目标

让管理员可以从一个工作区查看订单、生成任务、财务汇总和管理员审计，不需要直接查库或拼接多个接口。

### 范围

- 新增管理员订单查询：充值订单与订阅/渠道解锁运营订单统一列表，支持类型、状态、关键词和时间范围筛选；
- 新增管理员生成任务诊断列表：用户、模型、能力、渠道、状态、预占/结算积分和失败原因；
- 新增管理员审计日志分页查询；
- 新增财务汇总：充值笔数与金额、调用次数、收入/成本/利润积分、失败次数；
- 运营后台增加“订单与财务”工作区，复用 Ant Design 表格、统计卡片和筛选控件；
- 继续隐藏密钥、请求正文、完整上游响应和本地画布内容。

### 不包含

- 不在本阶段自动执行退款、支付冲正或外部支付写操作；
- 不调整充值比例，固定保持 1 元 = 100 积分；
- 不改变用户端模型、渠道和画布入口。

### 验收标准

1. 管理员可以按订单类型、状态、用户关键词和时间范围读取列表；
2. 订单列表不返回幂等键、支付密钥或支付回调原文；
3. 任务诊断可定位失败任务及其计费结果；
4. 财务汇总与使用日志价格快照一致；
5. 审计日志可分页读取并显示操作人；
6. 普通用户访问上述接口返回 403。

## 第三阶段：异步任务生命周期

### 目标

让托管生成任务的取消真正中断进行中的上游 HTTP 调用，并继续沿用现有预占、结算、订阅额度回退和幂等状态机。

### 范围

- Relay 为运行中的任务登记进程内取消句柄；
- 用户取消任务时先中断上游请求，再将任务转为 cancelled 并释放预占或订阅额度；
- 上游请求因取消返回时不重复扣费、不把已取消任务改写为 failed；
- 已完成任务、队列任务和重复取消请求保持幂等状态响应；
- 增加取消句柄单元测试。

### 边界

- 进程重启后无法恢复进程内 HTTP 句柄，仍由既有 stale-task 回收器负责释放额度；
- 远端已经完成但本地尚未收到响应时，以本地取消状态为准，不重复发起请求；
- 不增加新的超时、重试或并发上限，继续使用现有配置值。

### 验收标准

1. 运行中的任务调用取消接口后，上游 HTTP 请求收到 context cancel；
2. 任务最终状态为 cancelled，预占和订阅额度只释放一次；
3. 取消后的执行请求返回持久化任务状态，不产生第二次上游调用；
4. 已成功、失败或已取消任务重复取消返回明确状态错误；
5. `go test ./...`、前端类型检查和前端构建通过。
