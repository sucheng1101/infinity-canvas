# 生产发布 SOP

本文是 Infinite Canvas 的生产发布基线。当前应用是 Vite 静态前端，生产发布只替换 `image.helpapis.com` 对应的静态目录；`codex.helpapis.com` 的 NewAPI 进程、端口、配置和数据均不在本流程的变更范围内。

## 0. 发布红线

1. 发布提交必须同时推送至项目自己的 GitHub 和 Gitee 仓库；上游仓库只用于同步源码，不作为发布写入目标。
2. 两个远端的目标分支与发布提交必须完全一致，任一推送或校验失败即停止上线。
3. 只在本机构建。生产服务器只接收已完成 SHA256 校验的静态制品，不安装依赖、不执行前端构建。
4. SSH 连接必须先校验预先登记的主机名和 `ssh-ed25519` 指纹；主机信息放在本机私有环境配置中，不提交到 Git。
5. 只备份并替换从 `image.helpapis.com` Nginx 配置读取到的静态根目录，不猜测路径，不修改其他站点配置。
6. 切换前创建带时间戳的回滚备份；验收失败立即恢复该备份。
7. 密码、令牌、Cookie、环境文件内容及私有主机配置不得写入 Git、制品、日志、截图或发布记录。
8. 发布完成后删除本地临时归档、生成缓存和远端上传暂存目录；保留服务器回滚备份和应用数据。

```text
Gitee 远端提交：

```

发布记录只保存可公开的结果和提交标识，不保存凭据与私有配置内容。

## 2. 源码与双仓闸门

在仓库根目录完成版本整理、提交和标签后执行：

```bash
git status --short
git diff --check
git push github main --follow-tags
git push gitee main --follow-tags

COMMIT="$(git rev-parse HEAD)"
test "$(git ls-remote github refs/heads/main | cut -f1)" = "$COMMIT"
test "$(git ls-remote gitee refs/heads/main | cut -f1)" = "$COMMIT"
```

推荐远端职责：

```text
origin  上游源码，只读同步
github  项目自己的 GitHub 发布仓库
gitee   项目自己的 Gitee 发布仓库
```

## 3. 本机构建与制品校验

```bash
cd web
bun install --frozen-lockfile
bun run typecheck
bun run build

cd dist
tar -czf ../infinite-canvas-web.tar.gz .
cd ..
sha256sum infinite-canvas-web.tar.gz > infinite-canvas-web.tar.gz.sha256
```

构建目录和压缩包是临时发布制品，不提交到 Git。发布提交、`VERSION` 和 Tag 必须一致。

## 4. 目标核验与备份

生产主机参数通过本机私有环境配置提供，例如：

```text
IMAGE_HOST
IMAGE_HOSTNAME
IMAGE_HOSTKEY_SHA256
```

连接后按顺序执行只读检查：

1. 校验 SSH 主机密钥类型和 SHA256 指纹。
2. 断言 `hostname` 与登记值一致。
3. 读取 `image.helpapis.com` Nginx 生效配置，解析唯一静态根目录。
4. 记录发布前 `https://image.helpapis.com/` 与 `https://codex.helpapis.com/api/status` 状态。
5. 检查目标磁盘空间，并在独立 staging 目录上传制品与 SHA256 文件。
6. 在服务器重新计算 SHA256，完全一致后创建静态目录的时间戳备份。

备份目录与 staging 目录必须位于明确的发布根目录内，且任何递归文件操作前都要核对解析后的绝对路径。

## 5. 原子切换与回滚

1. 在与静态目录同一文件系统创建新版本目录并解压制品。
2. 检查 `index.html` 和其引用的主要静态资源存在。
3. 保留回滚备份后，以目录重命名完成切换，避免逐文件覆盖产生半更新状态。
4. Nginx 配置未变化时无需 reload；若上线要求涉及 Nginx，必须拆成单独变更并重新审批。
5. 自动检查或页面验收失败时，将静态目录恢复为本次发布前备份，并重复全部验收。

## 6. 验收清单

自动检查至少包括：

```text
https://image.helpapis.com/                     HTTP 200
image 首页引用的主要 JS/CSS                    HTTP 200
image 站点任一前端嵌套路由                    可回退到 index.html
https://codex.helpapis.com/                     HTTP 200
https://codex.helpapis.com/api/status           success=true
```

浏览器验收至少包括：首页打开、配置页、画布页、渠道与模型选择、重复 Key 提示，以及一次不含敏感内容的真实生成请求。浏览器控制台不得出现新增的资源加载错误。

## 7. 发布结束

1. 补齐发布记录、提交、Tag、双仓提交、制品 SHA256、备份路径和验收结果。
2. 删除本地发布压缩包、校验文件、临时脚本和本次生成缓存。
3. 删除远端本次 staging 目录，保留回滚备份和当前静态目录。
4. 清除当前发布进程内持有的 SSH 密码、Git 令牌与临时环境变量。

## 8. 其他项目复用

其他项目复用本流程时，保留“双仓一致、构建在本地、主机指纹校验、先备份后切换、自动验收、失败回滚、清理暂存”七个闸门；将项目类型对应的构建、备份、切换和健康检查写入各自仓库的项目 SOP。数据库、容器或后台服务项目需另外列出数据保护与服务隔离规则，不能直接套用本静态站命令。
