# 电商提示词与工作流调研

本文记录对公开电商视觉项目、提示词仓库和 ComfyUI 工作流的调研结果，用于规划 Infinite Canvas 的后续能力。外部内容只作为设计参考，不直接复制提示词、代码或素材；正式接入前仍需单独核对仓库许可证和上游变更。

## 调研结论

电商图片的核心不是收集一批“万能提示词”，而是建立一条可重复的生产链：

```text
商品资料/源图 → 商品事实 → 平台与人群 → 视觉套图规划 → 分角色生成 → QA/审核 → 修订 → 导出素材包
```

当前 Infinite Canvas 已经有图片、文本、配置、视频节点，支持参考图连接、批量生成、错误详情和生成记录。因此第一阶段不需要新增后端或接入 ComfyUI，可以先把电商生产链表达成一组可复用的画布节点和模板。

## 建议的提示词分层

### 1. 商品事实层

先把源图和资料整理成可核对的事实，不让模型自行补全：

```text
商品名称：[商品名称]
商品类目：[类目]
已确认外观：[颜色、轮廓、比例、纹理、五金、开合方式、标识]
已确认材质：[仅填写有源图或资料证据的材质]
已确认功能：[仅填写可验证功能]
包装/配件：[清单]
目标人群：[人群、地区、使用场景]
不确定信息：[待确认内容]
禁止声称：[没有证据的功效、认证、容量、防护或性能]
```

### 2. 视觉角色层

每张图必须有一个购物决策角色，避免只替换背景生成重复图片：

```text
平台：[平台]
图片角色：[主图 / 卖点图 / 使用理解图 / 材质细节图 / 尺寸图 / 对比图]
买家决策问题：[这张图要消除什么疑虑]
主信息：[只能有一个]
次信息：[可选]
构图：[主体位置、留白、安全区、视角]
镜头与光线：[焦段/视角、主光、辅光、阴影或倒影]
必须保留：[商品事实层中的身份特征]
禁止出现：[未证实卖点、竞品元素、水印、平台角标、随机配件]
```

### 3. 生成执行层

```text
以提供的商品源图作为身份参考。
只允许改变：背景、光线、场景、道具、模特、裁切和镜头角度。
必须保持：颜色、轮廓、比例、结构、五金、配件、标识、纹理和可见文字。
商品应是画面视觉中心，场景服务于商品，不得用氛围遮挡商品。
如某项信息无法从源图或商品资料确认，保持不可读或留空，不要编造。
```

### 4. QA 层

生成后按结构化结果检查，而不是只凭“看起来不错”：

```text
检查身份一致性：颜色、轮廓、比例、结构、材质、五金、标识、配件。
检查事实边界：是否出现未确认功能、材质、容量、认证或夸大承诺。
检查套图角色：每张图是否有不同且明确的购物决策作用。
检查平台适配：比例、信息密度、语言、留白、安全区和禁用元素。
检查文字：字词、数字、品牌、尺寸和单位是否来自已确认资料。
输出：通过项、问题项、证据来源、建议修订区域、是否需要人工确认。
```

## 三类首批模板

### 主图

适合货架、电商搜索和商品列表：

```text
为[平台]制作[商品]电商主图，目标人群是[人群]。商品占据画面主要面积，保持[身份特征]和准确比例，使用清晰、克制的商业产品摄影。背景干净，阴影自然，避免无关道具、徽章、虚假卖点和平台角标。图片目标是让用户在第一眼识别商品、颜色、形态和基本用途。
```

### 卖点/详情图

适合解释一个核心购买理由：

```text
为[平台]制作[商品]卖点图，只解释一个卖点：[核心卖点]。用[局部特写/剖面关系/操作动作/前后对比]把卖点变成可观察的画面，保留[身份特征]，采用清晰的视觉层级和可读留白。只使用[已确认事实]，不添加未经证实的性能、认证或夸张承诺。
```

### 使用场景图

适合让用户理解尺寸、动作和生活场景：

```text
为[平台]制作[商品]使用场景图，目标人群是[人群]，场景为[真实使用场景]。商品必须保持准确比例和结构，展示[具体动作/物品关系/尺寸参照]，光线和环境符合场景，人物和道具只用于说明使用方式，不得遮挡商品或改变商品身份。
```

## 平台适配建议

平台适配应表现为“信息优先级不同”，而不是简单替换背景：

- **货架型平台**：主图识别、尺寸/容量、材质细节、使用场景和决策总结优先，信息密度可以较高，但商品身份必须清晰。
- **内容型平台**：第一眼吸引、生活方式、封面停留和社交传播优先，仍需保持商品可识别，避免只做氛围图。
- **跨境平台**：目标国家的语言、单位、审美、场景和合规文案优先；本地化文字要在最终图片中再次复核。
- **品牌独立站**：统一品牌色、摄影质感、故事节奏和套图一致性优先，商品事实和价格信息仍需单独锁定。

第一阶段建议内置 `pinduoduo`、`taobao-tmall`、`jd`、`douyin`、`xiaohongshu`、`amazon` 六个轻量平台配置，只保存图片角色、比例偏好、信息密度、语言和禁用项，不直接承诺平台官方规则的完整覆盖。

## 画布节点映射

| 电商环节 | 画布节点 | 输入 | 输出 |
| --- | --- | --- | --- |
| 商品资料 | 商品资料节点（后续新增） | 名称、类目、材质、尺寸、SKU、平台 | 结构化商品资料 |
| 源图理解 | 图片节点 + 商品事实文本节点 | 一张或多张源图 | 可核对事实、未知项、身份约束 |
| 视觉规划 | 视觉规划配置节点（后续新增） | 商品事实、平台、人群、目标 | 套图角色和每张图的蓝图 |
| 生成 | 现有图片/生成配置节点 | 蓝图、源图引用、提示词 | 主图、卖点图、场景图 |
| 质量检查 | QA 文本节点或插件节点（后续新增） | 生成结果、商品事实、平台 profile | 通过项、问题项、修订 brief |
| 局部重做 | 现有编辑/遮罩流程 | QA 问题区域、源图、修订 brief | 定向修订图 |
| 导出 | 组节点 + 画布导出 | 已通过素材、平台和命名规则 | 平台素材包和 manifest |

## 第一阶段最小可行版本

建议按以下顺序落地：

1. **正式加入 `product-grid` Skill**：输入商品信息和源图，输出 3/6/9 张图片蓝图，包含图片角色、提示词、必须保留项、禁止项和比例。
2. **新增商品资料节点**：先采用轻量 JSON，字段覆盖名称、类目、材质、尺寸、卖点、目标人群、平台和 SKU；存储沿用浏览器本地持久化方案。
3. **增加三个内置模板**：主图、卖点/详情图、使用场景图；模板只负责组装提示词，不绕过现有图片请求链路。
4. **增加平台 profile 配置**：先覆盖六个平台的图片角色和输出偏好，允许用户在画布内修改。
5. **增加 QA 节点/面板**：先做人工确认清单和修订 brief，不在第一版承诺自动识别全部商品缺陷。
6. **增加电商运行日志字段**：在现有生成记录上追加 `projectId`、`productId`、`imageRole`、`platform`、`sourceNodeIds`、`promptVersion`、`qaStatus` 和 `revisionOf`，便于按商品项目追踪。

暂不建议第一阶段接入 ComfyUI、自动上架或全自动竞品抓取。先验证画布中的节点编排、提示词可复用性、身份一致性和失败修订闭环，再决定是否需要外部工作流运行时。
