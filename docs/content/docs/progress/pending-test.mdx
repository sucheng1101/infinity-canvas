# Pending Tests

## 优化 Wave 2：画布性能、存储兜底与模型目录

- 框选节点时应跟手（每帧一次更新），滚轮缩放不再抖；连续拖拽时项目只在停手后约 800ms 落盘。
- 把浏览器存储配额塞满（或在 devtools 里让 `localforage.setItem` 抛错）后拖动节点，应弹出「本地存储写入失败」提示，而不是静默丢改动。
- 手动把 IndexedDB 里 `infinite-canvas:canvas_store` 的值改成非法 JSON 后刷新，应提示「本地画布数据读取失败」并进入空白画布，不再永久停在加载壳。
- 电商画布（`/projects/:id`）自动聚焦节点时应避开底部工具栏，节点不被工具栏遮住。
- `/api/v1/models` 连续刷新多次，数据库中 `published_models` / `model_routes` 不应每次都被写入；只有在启动或管理端保存渠道后才会同步。

## 优化 Wave 1：画布健壮性、首屏、服务端与 CI

- 画布右上角菜单点「删除当前画布」应先弹确认框，确认后才删除；文案说明节点与本地图片都会清除。
- 用损坏或已失效的图片打开裁切/切分/放大对话框时，应提示「读取图片失败」而不是一直转圈；画布恢复失败时应看到错误页与「重试 / 返回项目列表」，不再永远停在加载壳。
- 导入损坏的图片/视频/音频文件时应弹出失败提示，不再静默无反应。
- 首屏：打开 `/login`、`/app`、`/workbench`、`/canvas/:id`、`/admin` 任一路由都应正常渲染，切换时短暂显示加载占位；`/workbench?mode=video` 不应加载图像工作台代码。
- 托管模式下取消一个已存在的他人任务应返回 404，且对方正在生成的请求不受影响。
- 上游返回超大响应（>32MB）时任务应判失败并回退预占额度，服务进程不崩溃。
- 充值订单超过 30 分钟未支付应被后台自动置为过期；过期后实际付款成功时仍应到账，且不会重复加额度。
- 账户服务收到 Ctrl+C / SIGTERM 时应打印关闭日志并在 60 秒内退出（可用 `SHUTDOWN_TIMEOUT` 调整）。
- 新增的 `.github/workflows/ci.yml` 应在 PR 上跑通 web（typecheck / test / build）与 server（build / test）。

## 本地一键启动（MySQL + 账户服务 + 前端）

- 双击根目录 `start-local.cmd`（或执行 `powershell -ExecutionPolicy Bypass -File .\start-local.ps1`）后，应先启动 MySQL、再启动账户服务、最后启动前端，并打印 `本地服务已就绪：http://localhost:1010`。
- 机器上还没有 `%LOCALAPPDATA%\InfiniteCanvas\mysql-data` 时，脚本应自动初始化数据目录、按 `DATABASE_DSN` 创建 `infinite_canvas` 库并绑定 DSN 里的账号密码，不需要手工建库。
- 启动完成后 `http://127.0.0.1:1011/healthz` 返回 `{"status":"ok","checks":{"mysql":"ok","redis":"ok"}}`，登录页不再出现「账户服务内部异常（HTTP 500）」。
- 关闭浏览器后重新执行一次，脚本应复用已在运行的 MySQL、账户服务和前端，不重复启动。

## 渠道配置流程与 8K 超分规则

- 管理员创建渠道后添加模型专用 Key，点击获取模型；同步出的模型应自动填入能力和官方质量标准，管理员可以手动覆盖后保存。
- 在渠道模型编辑中选择公开模型；已有公开售价时应只读展示，尚未设置时可在此填写对应能力的公开售价，再填写渠道成本并一次保存。
- 渠道编辑应从右侧打开，渠道模型编辑应从左侧打开；关闭任一抽屉后，另一层编辑状态和未保存输入应保持可继续操作。
- 官方质量标准不得出现 8K；8K 只在渠道开启超分且启用 8K 超分时作为可用分辨率出现，不支持 8K 的渠道不应在用户侧显示。
- 生图、视频、文本和音频应分别显示按张、按秒、按 Token 和按次售价提示；模型目录同时区分按次售价与订阅权益。

## 本地服务启动与账户错误提示

- `start-local.ps1` 在 MySQL 或 Redis 未监听时应显示对应地址并停止启动；不应关闭或重启其他进程。
- MySQL、Redis 正常且 `1010/1011` 可用时，脚本应等待 `1011/healthz` 中 MySQL/Redis 均为 `ok` 后再启动 Vite，并在 `1010` 前端探测成功后显示入口地址。
- 本机安装 MySQL 且项目专用数据目录已初始化时，停止 MySQL 后重新执行启动脚本应自动拉起 `127.0.0.1:3306`；其他主机、端口或数据目录不存在时仍应保留明确的依赖错误。
- 登录请求连接失败、HTTP 502/503/504、账户服务其他 5xx、结构化业务错误应显示各自对应的提示，不再共用“账户服务尚未连接”。

## 模型目录、渠道路由与定价联动

- 在渠道内绑定并保存一个新的上游模型后，模型目录应自动出现对应公开模型，不需要手动新增；模型目录仍可编辑展示名称、公开配置、状态和排序。
- 两个渠道提供相同能力、相同上游模型名时，目录只显示一个公开模型，路由列表也按公开模型合并成一行，并在行内展示各渠道。
- 路由优先级数值较小的可用渠道应优先；只有同一模型最低优先级的可用渠道按权重比例分配请求。禁用路由、渠道、渠道模型或移除专用 Key 后，该项不应参与分配，剩余可用渠道应接管请求。
- 路由列表显示的同级比例应只基于启用且渠道就绪的路由；编辑权重、优先级、启用状态后刷新页面，分组、比例与 Relay 实际调度保持一致。
- 渠道模型列表应通过“编辑”调整能力和调用脚本，通过“删除”移除模型，通过“禁用/启用”切换状态；保存渠道后这些状态应保留，禁用模型不能用于路由。
- 为合并后的公开模型发布一条定价后，该模型对应的所有渠道路由应共用同一个公开模型定价；切换渠道权重不应新增或改变定价记录。
- 托管模式配置中应展示“自定义渠道”页签和不可使用/需开通套餐提示，已保存的本地渠道仍可见但编辑不可用；本地模式渠道配置保持可编辑。

## 易支付充值链路

- 管理员在“账户与支付”中填写与 newapi 相同的支付地址、商户号、密钥，并填写支付网关可以访问到的“异步回调地址”；保存后密钥不应回显。
- 用户在充值页选择支付宝或微信支付，提交后应跳转到网关的 submit.php，下单参数应包含 device=pc，且签名与 newapi 一致。

## Hosted relay

- 托管模式图片、文本、音频和视频生成过程中触发取消时，应中止报价、任务创建或执行请求，并保持现有额度与本地节点状态不变。
- Administrator routes should map one published model to an active upstream channel model; Relay should use the dedicated key bound to that upstream model, and no channel key may appear in user responses.
- When the highest-priority route points to a hidden channel, an unbound model, or a missing dedicated key, Relay should continue to the next available active route.
- An authenticated user can create a quote, create a generation task, and call `POST /api/v1/generation-tasks/:id/execute`; the server should inject the configured upstream model and relay JSON requests for image, text, video, and audio capabilities.
- Upstream success should persist the response in the task and settle the reserved quota; upstream HTTP errors, missing routes, and unsupported capabilities should persist a failed task and release the reservation.
- Repeating the execute request after a terminal task should return the persisted task without sending another upstream request.

| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 | 5120 × 7680 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 | 7680 × 5120 |

| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** | **7680 × 4320** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** | **4320 × 7680** |

- 在画布和图像工作台逐项切换 4 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K、8K 的 1:1。
- 所有 4K、8K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
